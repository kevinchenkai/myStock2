0 摘要

要解决的问题。 你想要一个能随时看清自己账户的 Web 工具，并且让 AI 每天给出下一交易日的操作指导，最终证明"AI 指导的操作比我凭直觉赚得多"。V1 已经能采集、展示、预测次日高低区间，但它还不能公平地回答最后那个问题：账本不含费用与资金流水，人类基线是"被重新撮合"的模拟成交，各策略的资金约束不一致，预测区间也没有变成带数量与有效期的操作单。

方案：四个子系统，一条主线。

子系统 一句话 对应你的需求
账本 Ledger 账户事实的唯一真相：成交、费用、资金流水，可对账 G1
透视 Lens 只读视图集合，新增一个视图 = 新增一个文件夹 G1、G2
教练 Coach 每天对圈定标的生成"操作单"：动作、限价、数量、有效期、作废条件 G3、G4、G5
记分牌 Scoreboard 同起点、同费用、同约束下比较「人类 / AI / 买入持有」，并做逐笔复盘 G6、G7

四个关键押注（均可被证伪）。

  1. 先建记分牌，再优化模型。 没有可信的尺子，任何"改进"都是噪声（仓库自己的 Tier1 复检已经证明过这一点）。
  2. 用"策略袋 sleeve"做公平比较。 把圈定标的当成一个独立小账户：人类与 AI 从同一初始状态出发，人类按真实成交原样记账，AI 按冻结的操作单模拟，两边使用同一套费用模型与同一资金口径。
  3. 大模型只做"否决与解释"，不做"下单"。 LLM 可以取消或缩小买入单、标注事件风险，不能新增或放大任何操作单。这样既限制幻觉风险，又能把它的价值单独量化（有无否决两条线并行）。
  4. 个人历史交易用于画像与复盘，不用作价格预测标签。 样本少、行为噪声大；它最适合回答"我的操作哪里漏钱"。

证据强度提示。 以日度超额收益标准差 1% 估算，每天真实优势 5 个基点约需 3,100 个交易日才能在统计上识别，20 个基点也要约 200 天（§7.5）。所以验收分两层：工程验收必须通过；策略晋级允许"证据不足，继续观察"。

你需要先定的三件事（§11）： NV 是否指 NVDA；基准币种；核心仓与交易仓边界。

1 目标与可度量结果

1.1 需求原文与拆解

1）Web：通过 API (futu, yfinance) 获取个人实时数据和历史信息，搭建个人股票交易分析工具 —— 随时自定义功能和升级，如：我的持仓，我的交易，交易盈亏，资产趋势，美元汇率… 2）ML：在我圈定的优质标的 (e.g. NV/TSLA/0700)，合适价格 (低价买入/高价卖出)，天级别交易 —— 利用最先进大模型 (Fable/Astra)，结合我账号信息和历史交易做独立建模预测，给 T+1 操作指导；对人类操作（买入/卖出）做回放复盘，给出交易指导；持续优化目标：AI 算法指导的操作收益要大于我人类凭直觉操作的收益。

编号 目标 可度量结果（建议阈值，由负责人确认）
G1 个人实时/历史数据的分析 Web 每个页面显示数据新鲜度；持仓数量与券商一致，现金逐币种差异可逐项解释
G2 随时自定义与升级 新增一个只读视图只需新增一个文件夹，不改核心代码（§3.2）
G3 圈定优质标的 标的名单为配置文件；只接受完整富途代码（如 US.NVDA），不接受裸代码
G4 合适价格低买高卖，天级别 每个交易日对每个交易仓标的产出一张可冻结的操作单，或明确的"不操作"及原因
G5 大模型 + 账户 + 历史交易，T+1 指导 操作单的数量受账户约束；LLM 否决层可开关、可追溯、可量化
G6 对人类操作回放复盘并指导 每笔真实成交都有复盘卡；汇总出可检验的行为指标
G7 AI 收益 > 人类收益 记分牌在同口径下持续输出差值与置信区间；"晋级/继续观察/退役"有预注册规则

1.2 成功的两层定义

层 含义 性质
A 工程成功 账本可对账；操作单每日可生成、冻结、追溯；记分牌可复算；失败可见 确定性，必须通过（§9）
B 策略成功 预注册的协议下，AI 的费用后收益显著优于人类基线且风险未超限 概率性，允许不通过；不通过时 A 层价值仍成立

1.3 非目标

自动下单；全市场选股；多用户/SaaS；期权、杠杆、融资融券、日内高频；离线 RL 与端到端黑箱（仓库既有实验为负结果）；更换技术栈。出现多写者、远程部署或高并发需求时再另做架构决策。

3 产品设计

3.1 账本 Ledger

原则：订单是意图，成交是事实。账本只追加，更正用新事件，不改旧行。

ID 需求 优先级 验收要点
LG-01 事件类型：FILL 成交、FEE 费用、DIVIDEND 股息、SPLIT 拆合股、DEPOSIT/WITHDRAW 入出金、FX 换汇、INTEREST 利息、TAX 税费、ADJUST 手工调整 P0 每类事件至少一个合成用例
LG-02 幂等：事件主键由 来源:来源ID 稳定生成 P0 重复导入同一批成交，数量与现金不变
LG-03 部分成交逐笔记账；撤单、失败、未成交不产生账本事件；费用可晚于成交到达并关联到成交 P0 两次部分成交 + 后补费用，数量、现金、费用归属正确
LG-04 期初状态：以一个"开账日"的持仓与现金快照为起点，附成本来源标记 P0 开账日之前的卖出，不产生"精确盈亏"
LG-05 费用档案：按市场、方向、最低费用、比例费、固定费、税费与生效期建模；费率由负责人按自己券商条款填写，本书不预设数值 P0 实际费用与估算费用分列显示
LG-06 导入通道：富途接口为主；券商对账单 CSV 为补充；手工录入走 ADJUST；富途是否提供资金流水接口须在 P0 核验，否则入出金手工录入 P1 每个事件保留来源与原始引用
LG-07 对账：用事件重建的持仓与现金，对比券商当日快照 P0 持仓数量逐标的完全一致；现金逐币种差异在建议阈值内且逐项可解释；未对账项显式列出
LG-08 金额与数量用十进制（字符串存储，计算用 Decimal） P0 迁移前后旧成交的合计误差为 0 或有记录的舍入差

3.2 透视 Lens：视图即模块

目标：新增或升级一个页面，不碰核心代码。

  view.yaml    # 标题、导航顺序、参数定义、依赖的表、新鲜度策略、是否需要账本
  query.py     # run(conn, params) -> dict   纯函数，只读连接，无副作用
  panel.js     # 前端面板，使用公共的图表/表格/主题工具
  • 启动时自动发现 views/*，统一路由 GET /api/v/<view_id>。
  • 传给 query.run 的是 SQLite 只读连接（URI mode=ro）：把"Web 只读"从约定变成技术保证。
  • 公共约定由框架强制：金额带币种、涨跌红涨绿跌、汇率中性色、每个视图自带"数据新鲜度"头部。
  • 用户级自定义放在 config/views.yaml（启用/隐藏、顺序、默认参数），不进代码。
  • 迁移策略：现有页面渐进迁入视图模块，每迁一个就保持旧路由可用，直至新旧输出一致。
ID 需求 优先级 验收要点
LN-01 视图自动发现 + 只读连接 P1 新增示例视图仅新增一个文件夹，且写库操作被拒绝
LN-02 新鲜度头部：数据模式（日线 / 定时缓存 / 近实时）、事件时间、采集时间、陈旧度；未知时间不显示"新鲜" P0 每个视图都有；缺失显示"未知"

"实时"的分层（G1）。 页面打开时不直连富途。近实时由独立进程 quoted（P7）拉取报价写入缓存表，Web 读缓存并显示陈旧度。富途历史订单/成交接口限频为每 30 秒最多 10 次，且历史成交仅支持实盘；行情权限与额度依账户而定，不写死为通用能力。yfinance 定位为公开接口的研究/个人用途工具，不描述为券商接口，也不承诺实时。

操作单（ticket）字段：

字段 含义
target_session 目标交易日（HK 与 US 各按自身交易所日历）
action BUY / SELL / HOLD（持有，无操作）/ SKIP（不操作，附原因）
limit_price、qty、lot_size 限价、数量、每手股数；数量取整到手，价格取整到 tick
valid_from/to 有效时段（默认目标日正常交易时段）
reserved_cash 预留资金，含估算费用
invalidate_if 作废条件：持仓变化、快照陈旧、超过截止时间、关键数据被更正等
reason_codes 触发原因与阻断原因（如 no_edge、cash_insufficient、rule_unknown）
uncertainty 样本数、校准状态、区间含义
model_ref、strategy_version、protocol_version 溯源
frozen_hash、supersedes 冻结哈希；修改只能生成新单并指向旧单

首期策略：透明的库存策略（决策层是纯函数）。

decide(状态, 预测, 证券规则, 配置) → 操作单，无 I/O，便于测试与复算。

  • 边际门槛（edge gate）。 仅当预测区间足以覆盖往返成本时才出买单：(Ĥ − L̂) / 中间价 ≥ k × c_rt，其中 c_rt 为往返费用与滑点比率，k 为安全倍数。区间太窄＝没有交易价值，输出 SKIP(no_edge)。
  • 买单。 满足门槛、预算与交易仓上限允许时，按冻结的分位水平 q_buy 取限价，数量 = min(单标的预算切片, 可用现金) / 价格 向下取整到手。
  • 卖单。 仅对确认的可卖交易仓出单；价格条件为分位水平 q_sell 且不低于成本加最小获利 min_gain（可选），或触发时间止损。
  • 时间止损。 交易仓持有超过 max_hold_days 时，输出退出单。该值由负责人设定；缺失则不生成可执行数量，避免"低买没卖出就一路扛"被忽略。
  • 共享预算。 同一策略袋内多个标的共用同一份现金与库存；按冻结的优先规则依次预留。
  • 不强制取区间端点。 q_buy、q_sell、k、min_gain、max_hold_days 等参数写入版本化配置，在观察期开始前冻结，不依据事后高低点调整。
  • 不展示没有依据的概率。 没有触价概率模型时，不出现"成交概率 80%"之类的数字。
ID 需求 优先级 验收要点
CO-01 名单配置化 + 校验器 P1 增删标的无需改代码；NV 被拒并提示候选
CO-02 每个交易日、每个市场、每个交易仓标的产出一张操作单或 SKIP P0 覆盖率可统计，缺失有原因

时间约定（沿用 V1 shadow 协议并复核）： 收盘后生成基础操作单；开盘前（港股 08:30 HKT、美股 09:00 ET）刷新一次并在截止前冻结；超时记"错过截止"，不在收盘后回填为正式单。存储统一 UTC；区分 event_at（事件发生）、available_at（协议下可得）、received_at（实际接收）、generated_at（生成完成）；历史研究只能"按 bar 结束推定可得"时，标为假定可得。

3.4 复盘 Replay

对每一笔真实成交生成一张复盘卡，再汇总为行为指标。 全部为事后诊断，不定义"当时应成交的最优价"。

复盘卡内容 说明
事实 时间、价格、数量、费用、成交前后库存
当时的证据 成交前已存在的预测与操作单（如有）；你事前记录的意图（如有，否则写"动机未记录"）
执行质量 买入：(成交价 − 当日最低) / (当日最高 − 当日最低)，越小越好；卖出取反。当日区间退化时不计算
结果 成交后 1 / 5 / 20 个交易日的价格变化；持有期内最大不利变动与最大有利变动；平仓回合的费用后盈亏
对照 同一时点的 AI 操作单（如有）与"不操作"的反事实（保持当时信息与资金约束，标为模拟）

4 智能层

4.1 预测层

  • 沿用 V1 的次日 low/high 分位回归 + CQR 校准，生产默认不变。目标定义为 y_low = low_{T+1} / close_T − 1、y_high = high_{T+1} / close_T − 1，训练、校准、报告、回放使用同一口径。
  • 分别预测的 low/high 分位不自动构成有指定联合覆盖率的全天包络；CQR 的覆盖保证依赖可交换性等条件，金融时序须以实测覆盖率报告。
  • 风险覆盖区间与执行报价分别记录、分别评估：区间是不确定性的表达，报价由决策层产生。
  • 次日 low 可能高于昨收，high 也可能低于昨收，不得强行让区间跨越昨收。
  • 候选改动一次只改一个因素（标签 / 特征 / 校准 / 撮合规则）。已判定无效的路线（风险调整 reward、HMM 软切换、离线 RL）不因单次好结果复活。
  • 预测层晋级沿用仓库既有门槛（等权 raw pinball ≥5%、skill ≥3%、6 股中 ≥4 股方向改善），不得事后调低；预测增益与策略收益分别验收。

4.2 大模型：否决与解释，不下单

定位。 把 Fable / Astra 等高能力模型用在它擅长且可验证的位置：读事件与资料，判断"今天这张买单要不要放行"。

输入包（evidence pack）。 一张机械生成的操作单；近 N 日 OHLCV 摘要；带发布时间的事件与资料（财报日历、公告、新闻标题）；必要的账户摘要（已脱敏，不含账户号）。

输出（严格 JSON，经 schema 校验）。

{
  "verdict": "allow",              // allow | downgrade
  "adjustments": [],               // 允许的调整：cancel_buy | reduce_buy_qty
  "flags": ["earnings_within_2d"], // 事件风险标签，可附在任意操作单上
  "evidence_ids": ["ev-123"],      // 必须引用输入包内的证据
  "note": "不超过 200 字的说明"
}

不对称权限（硬规则）：

动作 是否允许
取消买单、缩小买单数量 允许
给任意操作单加事件风险标签 允许
新增操作单、放大数量、改限价 禁止
取消卖单 禁止（卖出是降低风险的动作）
写账本、触达券商、修改已冻结操作单 禁止

双线并行量化价值。 记分牌同时记录 ai（机械操作单）与 ai_veto（经 LLM 否决后的操作单）两条线，两者差异即 LLM 层的净贡献；另统计否决精度——被否决的买单中，事后若成交本会亏损的比例。

接入方式（分两步，降低依赖）。

  1. 人工通道： 系统导出输入包为 Markdown，你在 Claude 或 Codex 界面里完成判断，粘贴回 JSON，系统校验后导入。无需任何 API。
  2. API 通道（可选）： provider 适配器，记录提供方、实际模型 ID、prompt 版本、输入证据、输出、延迟、成本；日调用数、token 与金额设上限，超限停用而不影响账本与基础操作单。是否有可用 API、模型标识、权限与价格，由实施方核验，不假定开发界面名称等同稳定 API 名称。

安全与证据口径。

  • 外部资料中的指令一律当数据，不获得任何系统权限；发往外部接口的内容只含脱敏摘要。
  • 所有可检验的数字（数量、汇总、收益）由确定性代码计算，LLM 不自行重算；无证据的事实标"未知"，证据冲突标"冲突"。
  • 历史回测局限： 当前大模型可能在预训练中已见过历史事件的后续走势，因此用它对旧日期做否决，不构成无泄漏证据。历史上只用于工程测试；正式结论只依据从启用日起冻结的前向记录。
ID 需求 优先级 验收要点
IN-01 输入包导出与 JSON 导入（人工通道），含 schema 与权限校验 P2 越权调整（如放大数量）被拒绝并记录
IN-02 双线记录与否决精度统计 P2 ai 与 ai_veto 同期可比

角色 用途 是否进入价格预测

实验前登记假设、改变因素、候选数、窗口、seed、版本、晋级条件；时间有序切分，多日标签须隔离；调参、校准、最终评价窗口分开，已反复查看的窗口不再称"全新留出集"；分位水平与策略参数也属搜索预算；简单模型胜出就保留简单模型，失败候选记录原因。

7 评价协议

7.1 策略袋（sleeve）：公平比较的基本单位

定义。 一个策略袋 = 某币种下圈定标的集合的"独立小账户"。每个币种一个袋，币种之间不相加。

项 规则
开账日 D0 由负责人指定，之后不改
初始状态 袋内持仓 = D0 当日真实持仓中属于名单的部分；袋内现金 = 负责人设定的预算 B（每币种一个）
人类袋 human 名单内的真实成交按原样记账（时间、价格、数量原样，不重撮合）；名单外的交易不进入该袋
AI 袋 ai 从同一初始状态出发，按冻结的操作单在目标日的小时线上模拟成交（保守撮合，见 7.3）
否决袋 ai_veto 同上，使用经 LLM 否决后的操作单
买入持有 buyhold D0 用 B 加初始持仓，持有不动
费用 四个袋全部用同一份费用档案估算；实际费用另列，不参与比较
股息与拆股 四个袋用同一规则处理

资金口径。 人类袋的现金允许为负（现实中资金可能来自袋外）；AI 袋不允许为负。为避免对 AI 不公平，所有袋同时报告：绝对盈亏，以及按占用资金峰值（B + 现金负值的最大幅度）计算的收益率。

7.3 撮合与不确定性

  • 真实成交不撮合，原样记账。
  • 模拟成交：操作单有效期内的小时线若越过限价才视为可成交；同一根 bar 内先后顺序未知，同 bar 双边触达时不默认"刚买入的库存立即高价卖出"，按保守规则处理并标记歧义；触价不等于全量成交，成交量假设写入协议版本。
  • 必做敏感性：费用 ×2、加滑点、剔除双边歧义日。结果与主表并列呈现，不得为让结果好看改用更乐观的撮合路径。

7.4 公平约束

  1. 起点、预算、费用档案、股息规则对所有袋一致。
  2. 禁止按人类交易日筛选 AI 样本；禁止只统计盈利回合；禁止每天给策略重新充满本金。
  3. 缺少某条线操作单的日期保留在分母里，按其冻结的失败规则处理，并单列覆盖率。
  4. 固定规则的参数在开发阶段确定，不在测试段为基线反复选参。
  5. 用户在看过当日 AI 操作单之后才做的决定，标 seen_ai=1；没有意图记录的日子是"意图未知"，不算"选择不交易"。
  6. 人类基线与 AI 的对比不是严格的随机对照（人会受工具影响），结论措辞按此限定。

7.5 统计与证据强度

  • 主指标： 同日配对差 Δ_t = r_AI,t − r_ref,t（日度袋收益之差），分别对人类、买入持有、ai_veto 与 ai 之间报告。
  • 推断： 按时间块的成组重采样，同一日期的名单内全部标的一起抽样，保留跨标的相关；报告效应值、样本量与置信区间；登记所有尝试的候选与参数搜索预算；最终以未查看窗口或前向观察确认。
  • 功效的现实检验（示意，σ 为假设值，P0 用真实数据重估）。 对日度配对差做均值检验，所需交易日数约 n ≈ ((1.96 + 0.84) × σ / μ)²（双侧 5% 显著、80% 功效）。σ = 1% 时：
真实的日均优势 μ 所需交易日数 n
5 bps（0.05%） ≈ 3,100（约 12 年）
10 bps（0.10%） ≈ 780（约 3 年）
20 bps（0.20%） ≈ 200（不到 1 年）

含义：小优势在一年尺度上多半无法与噪声区分。因此前期应同时盯过程指标（操作单覆盖率、预测校准、成交假设稳定性）与经济意义，不把一个收益数字当成证明。 - 结论范围： 个人账户与有限标的下的证据，不外推到所有股票、行情或他人。

9.2 必测业务反例

  1. 开账日之前就有卖出：不产生精确盈亏，标"估算"或"不可用"。
  2. 三只标的同时触发买入而现金只够一笔：按冻结规则分配，其余输出 SKIP(cash_insufficient)。
  3. 一笔订单两次部分成交 + 后补费用：数量、现金、费用归属正确。
  4. 撤单、失败、未成交、手工更正：不重复计入。
  5. 同 bar 双边触达、跳空、缺 bar、停牌：记录歧义与不可执行。
  6. 拆股、除息、股息到账、跨币种费用：现金与权益分别核对。
  7. 大额入金当天标的下跌：入金不显示为收益。
  8. 港股长假、美股节假日、夏令时、半日市：目标日与截止时间正确。
  9. 任务在截止前启动、截止后完成：拒绝作为合规操作单。
  10. 主数据源过期而备用源有效、部分成功、空结果：逐标的选源并保留失败记录。
  11. LLM 返回放大数量、新增操作单或取消卖单：被拒绝并记录。
  12. LLM 超时或输出非 JSON：否决层关闭，机械操作单照常。
  13. 用户看过 AI 后补录"独立想法"：记录真实时间与 seen_ai=1，不算独立对照。
  14. 相同操作单重跑、页面刷新、配置修改：已冻结的单与已评分的结果不可覆盖。
  15. 公开导出与私有模板混用：私有字段不得出现在公开文件。
  16. 名单写 NV：校验器拒绝并给出候选。
