1 项目定位与核心结论

myStock 面向个人投资者，服务于用户自己圈定的港股和美股：持续掌握账户、持仓、交易与资产变化，在每个交易日前形成有证据、有价格条件、有资金约束的操作计划，并在交易后评估预测、执行与个人决策。

V2 的核心目标是建立一个可以长期验证和改进的交易辅助闭环：账户事实可信 → 下一交易日计划明确 → 人类自主执行 → 真实成交复盘 → 费用后收益比较 → 候选策略前向验证。长期目标是 AI 指导的操作优于个人凭直觉操作；该目标是待检验的产品假设，不能写成现有模型已经实现的能力。

现有 V1 已经具备数据采集、Web 展示、独立 ML 管线、区间预测、版本留档和前向候选入口。V2 应以渐进重构保留这些资产，把主要工程投入用于账本、时点证据、策略计划和统一评价。直接重写全部系统或同时更换框架、数据库与模型，会使收益变化难以归因。

项目层次 V2 要回答的问题 交付结果
资产事实 我持有什么，发生过什么，真实赚亏多少 可对账的账户与交易账本
市场预测 下一交易日可能怎样，误差和不确定性多大 版本化的预测与数据依据
操作决策 在我的资金和持仓限制内，什么条件下考虑操作 可执行但不自动下单的条件计划
人类复盘 我为什么操作，是否符合事前计划，偏差在哪里 事实与事后分析分开的复盘
效果验证 AI 是否带来费用后的收益增量，承担了什么风险 统一协议下的策略比较与前向记录

1.1 三项概念必须分开

预测好坏与交易好坏。 高低价误差下降，可能没有增加收益；区间覆盖率提高，也可能使买价过低、卖价过高，长期无法成交。

账户收益与已实现盈亏。 一直没有卖出不代表没有风险；只看已实现盈利会掩盖套牢库存。策略效果必须计入期末持仓、现金、费用和公司行动。

AI 研发工具与运行时 AI。 Claude Fable、Codex Astra 可以帮助研究、编码、审查和建立模型。它们也可以通过经过验证的接口作为运行时研究助手，但不能因为参与开发就把全部收益标记为“大模型预测收益”。

1.2 版本命名

“项目 V2”指本次产品和架构重构。仓库已有 feature_version='v2' 指开盘前特征候选，两者不是同一个版本。实施时分别记录 application_version、feature_version、model_version、strategy_version、protocol_version，避免将 UI 升级误写成模型晋级。

2.3 交易频率与 T+1 定义

T+1 指当前决策对应的下一市场交易日，不指自然日，也不指结算周期。港股与美股按各自交易所日历确定下一交易日，不能把美股最新数据的日期直接当成港股决策日。

“天级别交易”指以每日计划为单位，可持有多日；不要求每日买卖，也不要求同一天低买高卖。首期支持等待、继续持有、分批买入、减仓和退出计划。没有合适机会时，不交易是合法输出。

5 产品功能说明

5.1 账户总览

展示各币种现金、可用资金、冻结资金、持仓市值、账户权益、当日变化和数据状态。原币种金额始终可查；选择基准币种后才能显示合计，显示换算时间、汇率来源与缺失情况。

账户权益优先与券商账户快照对账。重建权益采用现金加持仓盯市加应收减负债，不能只把所有股票市值相加。首期长仓股票策略不使用融资额度当作自有现金；如真实账户存在融资、利息或其他资产，纳入账本或显式限定覆盖范围。

5.2 我的持仓

保留数量、可卖数量、均价、市值和浮盈，新增核心持仓与交易仓的区分、当前计划、集中度、最近一次对账状态。券商平均成本、摊薄成本、本地移动平均成本分别保存，不能互相覆盖。

核心持仓是否允许卖出、交易仓上限以及是否允许加仓，由用户设置。AI 不将用户长期持仓默认全部当作短期可交易库存。

5.3 我的交易与资金账本

订单是意图，成交是事实：撤单和失败订单不产生交易盈亏；部分成交按每笔 fill 记账。支持多个成交对应同一订单、费用后补、撤销或更正，以及交易、入金、出金、股息、拆股、换汇、税费和利息等事件。

支持券商导出文件作为官方接口的补充。导入必须可重复执行而不重复记账；手工修正用追加更正事件，保留原始来源。缺失费用时展示费用前值或明确估算，不输出“真实净收益”。

5.4 交易盈亏

至少区分已实现净盈亏、未实现盈亏、账户费用后权益变化、外部资金流、成交净现金流与汇率影响。历史成本不全时显示可信度和缺口，不利用当前成本把结果装成已知事实。

默认管理口径可沿用移动平均成本，FIFO 用于交易回合诊断。两者均保留定义和版本；二者在部分仓位卖出后产生的已实现金额不要求相同，完整权益核对则使用同一真实事件集。

5.5 资产趋势与汇率

分别展示账户权益、外部入出金和剔除外部资金影响的收益曲线。原有持仓市值走势保留，但名称必须是“持仓市值”，不能称账户净值或策略收益。

扩展汇率主数据，覆盖实际账户需要的 USD、HKD、CNY 换算路径。已有 USDCNY 页面继续保留；HKD 与 USD 的合并必须有明确汇率，不因汇率近似稳定就直接相加。股票涨跌保持红涨绿跌，汇率采用中性色。

5.6 自选标的与个股详情

用户维护名单、关注理由、持有目的和允许的操作。展示原始价格、复权走势、公司行动、事件、持仓、历史成交与预测。财报、公司资料或新闻必须显示发布时间；当前资料不能未经处理回填为历史可用特征。

“低价买入、高价卖出”是相对指定决策时点、期限与用户策略的价格条件，不能将跌幅大自动解释为低估，将上涨自动解释为应卖出。

5.7 下一交易日计划

每个市场有独立计划日期、截止时间和最终版本。用户首先看到“是否有计划、是否仍有效、需要什么条件”，再看预测与研究解释。

展示项 必须说明
目标日与市场 HK 或 US 的实际交易日
当前状态 可用、等待数据、错过截止、数据不足、已过期
推荐动作 等待、持有、考虑买入、考虑减仓、计划退出
价格条件 限价或价格区间、有效时段、触发条件
数量约束 可用资金、可卖库存、每手和价格规则、交易仓上限
作废条件 关键数据失效、持仓变化、超过截止、事件风险或用户撤回
不确定性 样本数、历史校准状态、区间含义和数据局限
证据入口 预测版本、账户快照、报价来源和策略版本

计划不得只有一句“明天买入”。买卖价不强制来自风险区间的两个端点；正式报价由经验证的策略层产生。没有触价概率模型时，不编造“80% 成交概率”。

5.8 人类操作复盘

先展示真实成交与事前意图，再解释差异。日复盘关注是否遵守计划、价格偏差和资金变化；交易周期复盘关注持有时间、净盈亏、持仓路径和重复行为。

个人历史交易用于分析行为、风险偏好和约束，不作为市场价格的“正确答案”。系统可以识别平均加仓频率、追涨、过早减仓等待验证模式，但必须附样本与定义。不能将所有亏损归因为错误，或将所有盈利归因为正确。

5.9 策略实验与比较

展示策略身份、数据区间、资金来源、费用、版本、样本覆盖率、权益、回撤、资金占用及失败情况。历史重建、时点未知历史和正式前向记录分别统计。研究人员可下钻某日看到当时输入、冻结计划、成交规则和完整账本。

6.1 职责分工

先将个人账户作为决策约束和效用选择输入，市场历史作为预测训练输入，个人交易作为行为研究和人类比较输入。三者隔离后才考虑更深的联合建模。

6.2 数值预测目标

沿用次日 low/high 相对决策基准价的目标，并明确价格口径。示例定义为 y_low = low_next / close_T - 1，y_high = high_next / close_T - 1；模型训练、校准、报告和回放必须使用相同定义。[R09]

分位回归预测的是目标的条件分位；两个分别预测的 high/low 分位，不自动组成一个有指定联合覆盖率的全天包络。CQR 为 conformalized quantile regression，用历史校准残差调整区间；金融时间序列存在分布变化，页面应报告实际覆盖，不能把理论条件未经说明转成确定保证。

风险覆盖区间用于表达不确定性，执行价格用于交易策略。二者分别记录、分别评估。次日 low 可能高于昨日 close，high 也可能低于昨日 close，不能强行让所有区间跨越昨日收盘价。

新增收盘收益、最大不利变动、触价概率或多日目标，都作为独立候选实验；不得在一次“换模型”中同时更换标签、特征、校准和撮合规则。

6.3 模型路线

保留当前 LightGBM 及朴素波动基线，冻结生产结果。CatBoost、XGBoost、简单尺度与线性候选的既有负结果保留。开盘前特征候选继续做前向验证，具体是否晋级依据其当前协议及新收益协议，不依据本次项目版本号。

预训练时序模型、表格基础模型、多模型组合、行为个性化策略可后续探索，但必须限定搜索预算。模型选择依据数据、稳定性、费用后结果和运维成本，不以“最先进”称谓作为验收条件。首期无需新增 GPU 或从头训练大模型。

6.4 大模型接入

“Fable/Astra”在需求中表示用户选用的高能力助手。具体是否提供可用 API、模型标识、工具权限、价格与数据策略，由实施方核验；本项目书不把开发界面名称假定为稳定 API 名称。

运行时设计为可选 provider 适配器，记录提供方、实际模型 ID、配置、prompt 版本、输入证据、输出、延迟和成本。没有可用 API 时，采用人工导入的研究稿，不阻塞数值计划。

LLM 输出分两条路径：基础路径生成解释，不能改变已冻结的确定性动作；研究路径可以产生独立候选计划，经 schema 和资金校验后记录为 challenger，前向证明有效再考虑进入正式策略。

所有可检验数字由确定性计算服务提供。LLM 不自行重算持仓数量、币种汇总或收益。没有证据的事实显示未知，证据冲突时标注冲突。资料中的指令不获得系统权限；研究助手无 broker 下单或账本写入能力。

6.5 LLM 历史回测的特殊限制

即使只给旧新闻，当前大模型也可能在预训练中知道后来的结果。因此，用当前 LLM 对旧日期生成买卖意见，不自动构成无泄漏的历史策略证据。可将其用于工程测试与探索性复盘；正式 LLM 增量结论主要依赖从现在开始冻结的前向输入、输出和实际可用时间。

7 交易计划与资金约束

7.1 计划生成顺序

  1. 验证交易日、数据截止、账户状态和标的名单。
  2. 读取合格的预测版本与必要市场证据。
  3. 用冻结策略配置生成候选价格与动作。
  4. 在组合层分配预算，预留现金和可卖库存。
  5. 按证券规则舍入价格与数量，重新计算含费用预算。
  6. 检查事件、持仓限制、报价逻辑与有效期。
  7. 冻结最终计划与全部引用，页面只读展示。

所有股票共用同一账户预算。单股回放可以用于诊断，但三只股票分别使用全部本金的结果不能相加成账户收益。多个市场重叠的持仓与换汇也必须进入统一预算。

7.2 首期策略

首期采用透明的库存策略：有合适买价且资金和交易仓允许时生成买入候选；有可卖交易仓且达到卖价条件时生成减仓候选；条件不足则等待。报价公式和仓位规则用独立配置固定，不依据当日事后高低点调整。

从多日持有出发制定退出政策，例如到期评估、价格条件或事件条件。最大持有天数、亏损承受约束与交易仓限制由用户配置，缺失时不生成可执行数量。首期不预设适合用户的风险比例。

不同退出规则视为不同策略版本。继续持有必须计入库存盯市，不能靠延后卖出隐藏亏损。达到上限、禁止加仓、缺少可卖数量或遇到未知规则时，输出具体的阻断原因。

7.3 首期边界

自动下单关闭。计划中的卖出不允许超过经确认的可卖库存；不默认允许借券、融资或以尚未结算资金扩大交易。实际可用资金和结算约束通过券商账户信息及生效规则确定，不能把交易信号 T+1 与结算规则混用。

盘前计划以目标市场正常交易时段为默认有效范围。盘前或盘后成交策略需要独立时间与撮合协议。现有港股候选有 09:00 HKT 截止等规定，先复用其冻结协议；如改变时间，则建立新的版本。

7.4 作废与更新

冻结后允许生成新版本，但必须保留旧计划。正式比较采用事先声明的选择规则，例如截止前最后一个成功冻结、已可供用户查看的正式版本。规则在观察期开始前固定，不因事后收益选择最佳版本。

持仓发生变化、关键数据被更正或用户撤回时，旧计划状态变为失效；生成的新计划记录关联关系。即使已经失效，旧版本仍保留用于解释当时行为。

8.2 实时的分层定义

V1 的手工 update.sh 是最新缓存，不等于持续实时。V2 页面统一显示数据模式：历史日线、定时缓存、近实时报价或推送报价。每种模式显示事件时间、采集时间、允许陈旧度和连接状态。

P0/P1 保留手工采集；近实时采集作为 P2 的独立 worker。用户打开页面不会直接触发 Futu 或训练。调度建议可写入实施方案，但本次文档交付不创建 cron/launchd。

8.3 四类时间

另外记录 decision_at、data_cutoff、target_session 和 deadline_at。前向计划要求所使用证据在决策前确实可得，生成完成在截止前。历史研究若只有“按 bar 结束时刻推定可得”，标为假定可得，不能补造真实接收时间。

8.4 原始价格与复权

原始成交价与当时交易价格用于资金记账；复权数据用于规定的特征与连续收益计算。拆股、股息、配股和其他公司行动通过独立事件处理，不能把复权价拿来虚构真实成交金额。

分红在除息日可能形成应收权益，只有支付日证据出现后才进入可用现金；当前回放已有应收处理，应继续补足到账与税费。拆股调整数量与单位成本，零碎股和现金替代有明确规则。当前复权序列可能包含事后调整，历史研究需记录数据版本和时点限制。

8.5 质量状态与失败处理

统一状态包括有效、陈旧、缺失、权限不足、来源异常、等待收盘、部分成功及规则未知。缺失不能记零，上一日数据不能贴成今日新数据。逐标的选择合格主备源，保留两者证据和最终使用来源。

失败不推进成功水位；重试幂等。必要数据失败则不生成新计划。旧计划可展示，但有原始目标日期和过期标识。评分同时统计成功样本、计划日分母、迟到、失败与数据缺失，不只报告成功行的效果。

9 统一账本与收益定义

9.1 账户事实模型

采用原始事件追加、派生状态可重算的模式。事件包含交易账户、币种、标的、事件类型、发生时间、现金变动、数量变动、费用、来源 ID 和更正关联。原始成交不能被研究结果覆盖。

期初状态包含现金、库存、成本来源和必要应收。历史不完整时，只对可对账的期间形成正式账户收益；不完整期间继续展示交易事实与估算诊断。

9.2 费用与精度

费用至少支持按订单、成交或账期导入，并保存币种、类型和生效版本。需要估算时，费用配置区分市场、账户、买卖方向、最低费用、按金额费用和必要税费，不能一律用一个固定 bps 声称还原券商费用。

财务计算使用 Decimal 或最小货币单位，避免长序列 float 累计误差。价格按 tick 表和区间规则舍入；港股不能假设历史始终是同一 tick 或每手股数。旧 REAL 数据保留，迁移时验证误差，不盲目重写全部历史。

9.3 指标定义

指标 定义与用途 注意事项

10 公平评价 AI 与人类操作

10.1 三种不同的问题

问题 方法 能得出的结论
人类过去实际赚了多少 按券商真实成交、资金流与期初状态记账 观察到的人类账户结果
相同历史条件下某策略可能如何 冻结初始资金、约束、策略和模拟规则进行回放 在明确撮合假设下的历史模拟结果
从现在开始 AI 是否带来增量 事前冻结的人类意图与 AI 计划、前向模拟及实际执行留档 前向证据，仍需注明行为影响和执行差异

真实成交与模拟策略可以用于诊断比较，但成交真实性不同，不是严格对称的实验。正式策略对照优先让 AI、简单规则与人类事前计划经过相同模拟协议；真实账户结果单列验证执行。

10.2 对照组

至少保留当前生产策略、朴素波动规则、买入持有、候选 AI 策略和人类计划。固定规则用开发阶段已确定的参数，不能在测试段为基线反复选差参数。

“人类无 AI 计划”只有在用户查看当天 AI 计划之前已记录意图，并且未受到历史 AI 学习等影响的限定条件下，才具有相应解释。用户已经看过 AI 后作出的操作应标记 AI assisted。空白日志是意图未知，不能算人类选择不交易。

系统分别支持基于人类计划的同协议模拟、真实成交账本和混合辅助实际账户。它们回答不同问题，不合并成一个“打败人类百分比”。

10.3 公平比较约束

各策略使用相同观察期、初始现金、初始库存估值、外部资金流与账户边界；各自后续持仓和交易由自身策略决定。收益、现金预留、结算、费用、股息与退出口径一致。

禁止按真实人类交易日筛选 AI 样本，禁止只选已盈利卖出的回合，禁止在每日重新给策略充满本金，禁止用期末真实持仓倒推 AI 历史可用库存。缺少某个策略的计划时保留该日，依照其冻结的失败政策处理并单列覆盖率。

10.4 撮合与不确定性

真实成交按实际 fill 入账，不重新撮合。模拟限价需要先确认订单提交时间和有效期，再判断之后的价格路径。价格触及仅代表可成交条件，不保证全量成交。

日线不足以判断先低后高；小时线仍有同 bar 歧义、排队和流动性限制。首期可沿用保守撮合，并输出成交假设、歧义天数及敏感性范围。必要时采用更细粒度数据，但不能仅为展示更好收益改用更乐观路径。

同一 bar 双边触达时，禁止默认为新买入的库存立即以高价卖出。可卖库存、现金与订单预留按提交时状态计算。费用加倍、价格滑点、排除模糊双边成交等预注册敏感性检验必须保留。

10.5 结果与统计

主指标为同协议组合的费用后收益差 Delta_R = R_AI - R_reference，分别相对人类计划、当前生产、简单规则和买入持有报告。风险同时报告最大回撤、亏损尾部、平均与峰值资金占用、换手、交易次数和期末库存。

预测辅助指标包括 raw pinball loss、校准后覆盖与区间宽度；它们不替代净收益。触价命中、订单成交、完整回合盈利均采用自己的分母，不互相替代。

统计比较使用按时间块成组的重采样，同一日期的全部股票一起抽样，保留跨股票关联。报告效应值、样本量与置信区间；短样本年化仅作辅助，不能放大为长期承诺。比较很多候选时登记全部尝试与搜索预算，最终使用未查看窗口或前向观察确认。

这仍是个人账户与有限标的范围下的证据，不能外推为对所有股票、所有行情或其他投资者都有效。

11 个人交易复盘方法

11.1 复盘分层

层次 内容 数据要求
事实层 实际买卖时间、价格、数量、费用、前后库存 券商成交与账本
决策层 当时目的、事前计划、可见证据与 AI 使用情况 决策前冻结日志
执行层 实际与计划的价格、数量、时间差异及原因 计划、成交、市场报价
结果层 费用后权益、最大不利变动、持有周期和机会成本诊断 成交后行情与预定评估期限
改进层 一个可检验的行为调整与后续观察 足够样本、明确规则和新前向版本

买卖后的最高或最低价属于事后诊断，不能拿来定义“当时就应该成交的最优价”。比较延后卖出或少买一笔属于反事实分析，必须保持当时已知信息和资金限制，并标为模拟。

11.2 输出模板

每份复盘包含：发生了什么；当时记录的目的；哪些证据确实在操作前可见；哪些行为偏离计划；收益或风险变化由价格、数量、费用或持有时间中的哪部分造成；有哪些无法判断的缺口；下一观察期只改变什么。

LLM 可以把这些结果组织成自然语言，但不能用事后新闻补写人类动机。没有日志时写“动机未记录”。建议以规则和可检查行为表达，例如“后续记录加仓前的总库存与退出条件”，避免不可验证的心理评判。

12 技术架构与模块边界

12.1 架构选择

首期保留 Python、Flask、SQLite 和现有静态前端，采用模块化单体加独立运行管线。无需同时引入 React、FastAPI、PostgreSQL、消息队列和 Kubernetes。出现多用户、多写者、高并发或远程部署需求时再提交架构决策。

架构关系为：外部来源 → 采集适配器 → 原始事实与账户账本 → 冻结研究快照 → 预测与计划管线 → 版本化产物 → 只读 Web 与报告。个人日志通过受控 CLI 写入，研究助手只消费经过裁剪的输入。

模块 职责 可写数据 边界
collectors 外部接口、分段请求、重试和来源证据 原始缓存与采集记录 不作策略决策
ledger 新增 事件规范化、余额、成本、权益、对账 账户派生表与更正记录 不生成预测
research 或现有 ML 数据层 冻结快照、特征、标签与实验输入 研究库与快照文件 不回写账户事实
ml 预测、校准、shadow 与模型产物 ML 库与模型产物 不依赖 Web
decision 新增 候选报价、组合预算、计划冻结 计划与决策日志 无真实下单入口
evaluation 整合 真实事件记账、模拟执行、统一指标 评价结果与事件留档 不训练或修改历史计划
assistant 可选 LLM 研究、解释与候选 研究输出与调用元数据 不能写账本或绕过校验
web 页面、查询、来源与证据展示 首期不写数据库 不抓取、不训练
pipelines 与 CLI 调用以上服务、记录运行状态 所属模块数据 明确命令与可恢复运行

建议逐步把 Web 使用的结果类型和查询层抽离训练导入；不因目录命名需要一次性搬动全部代码。已有 ml/models.py 作为实验适配层，优先扩展而非重复建设。

12.2 只读边界与日志写入

当前 AGENTS.md 明确 Web 只读数据库。[R01] 首期保持这个约束，新增 CLI 用于维护名单、记录意图和确认计划，Web 只显示结果。若后续需要网页直接录入，单独设计受限 command 服务，更新架构约定并处理鉴权与 CSRF；不能偷偷在 GET 接口中写入。

只读页面允许基于冻结输入进行纯计算，但正式报告和比较优先读取已留档结果，避免页面每次重算时规则版本漂移。

12.3 运行与隐私

本地服务默认仅监听回环地址，账户与密钥放在环境变量或私有配置，真实库和输入证据不提交公开仓库。远程 API 只接收完成任务所需的脱敏摘要；原始券商账户号、密码和完整交易库不作为默认 prompt 内容。

私有本地报告展示个人资产；公网报告使用独立导出模板，只包含允许公开的行情研究与协议摘要。增加私有字段必须经过模板白名单控制，不能让既有 publish 命令自动带出账户信息。

14 每日工作流程

14.1 收盘后

确认当日市场结束并取得完整行情；同步真实成交、费用和资金事件；对账现金与库存；生成基础预测；结算已成熟的预测和前向记录；完成日复盘；按需要构建私有报告。

美股收盘不会直接触发港股相同日期的结算。港股长假期间可能有多个美股交易日，新 ADR 特征必须按既有完整窗口规则处理。

14.2 开盘前

用户可先记录独立人类意图；采集候选所需的有效隔夜或盘前证据；在截止前完成数值预测和组合计划冻结；用户查看并自主决定。迟到的任务记录错过截止，不在收盘后回填为当时的正式计划。

收盘后计划与开盘前计划有独立协议。比较主表只使用预先指定的一种正式决策时点，辅助表可比较两个时点，不事后挑收益较好的版本。

14.3 交易后

导入真实成交，更新账本并记录人类覆盖计划的原因；计划更新生成新版本；目标日收盘数据确认后再结算预测。交易回合尚未平仓时，继续显示持仓风险，不能把回合标为已胜或已负。

15 重构实施计划

15.1 实施原则

建立隔离分支或工作树，先核验本机未提交改动和原运行库，使用一致性备份而不是复制正在写入的 SQLite 文件。保存恢复路径后，在副本上迁移与实验。旧页面、历史报告与冻结实验可追溯。

纯重构先以合成固定样本验证行为等价；随后对明确的计算修正单独变更版本。模型改变、资金口径改变与 UI 改变分开交付，以免无法判断效果来自哪里。

16.2 必测业务反例

  1. 没有期初买入记录却发生卖出：不生成无依据的精确净盈亏。
  2. 三只股票同时触发买入而资金只够一笔：按冻结分配规则执行。
  3. 一笔订单有两次部分成交与后补费用：资金和归属费用正确。
  4. 撤单、失败、未成交和手工更正：不得重复计入收益。
  5. 同 bar 双边触达、跳空、缺 bar 与停牌：记录歧义和不可执行。
  6. 拆股、除息、股息支付和跨币种费用：现金与权益分开核对。
  7. 大额入金当天股票下跌：不能把资金注入显示成投资盈利。
  8. 港股长假、美股节假日、夏令时及半日市：目标日与截止正确。
  9. 任务启动在截止前、完成在截止后：拒绝作为合规计划。
  10. 备用源有效而主源过期、部分成功或空结果：逐股选源且保留失败。
  11. 模型后端缺失、LLM 超时、输出非数值或改币种：明确失败或关闭研究，基础页面继续可用。
  12. 用户看过 AI 后补录“独立想法”：记录实际时间与暴露状态，不能算独立对照。
  13. shadow 不成熟、历史未知时点、回填报告：不混入正式前向计分。
  14. 相同计划重跑、页面刷新和用户修改配置：旧计划与已评分结果不可覆盖。
  15. 公网导出与私有模板混用：私有字段不进入公开文件。

数值与账本测试采用有意义的固定业务事件，不按当前实现照抄断言。页面检查覆盖主要桌面宽度与窄屏，确认金额不截断、币种可见、异常状态和来源证据可找到。

16.3 策略验收

工程通过即交付可用系统，策略晋级另设评价。沿用已有候选的冻结样本要求：公开待办记录每市场至少 60 个计划日、主力逐股至少 60 个合规配对，实施时核对实际有效记录。[R07][R08] 这属于观察下限，不是自动证明统计显著。

新增交易策略在观察前登记：比较组、资金、正式决策时点、费用、退出政策、主指标、最小有业务意义的增量、回撤容忍差、缺失处理与观察长度。未经确认的风险参数不能替用户填成实际交易配置。

建议判定规则：费用后增量达到预注册的实际意义要求，时间块置信区间与敏感性结果支持改善，风险未突破预注册约束，增量不完全依赖单一标的或少数模糊成交。若收益证据不足，保持研究或辅助身份并延长观察；不能在数据出来后调低门槛。

收益无法保证，且用户行为会受到工具影响，因此可报告“本观察期同协议 AI 计划优于该人类计划基线”或“辅助账户结果改善”；不声称已经证明 AI 对人的稳定因果优势。

17 模型实验与持续优化

实验前登记假设、改变因素、候选数、训练窗口、校准段、评价段、seed、版本和晋级条件。遵守按时间训练、向未来测试；不能随机打散交易日。[S05]

训练段、调参段、校准段和最终评价段明确分开。已经反复查看的旧窗口属于开发证据，不再命名为全新 holdout；多日持有和重叠标签需要相应隔离或 purge。分位水平、组合权重和退出参数也属于搜索预算。

新增模型分三道评审：预测质量能否改善；共同交易协议下是否有费用后价值；前向运行是否稳定。简单模型胜出就保留简单模型，候选失败记录原因与边界，避免重复昂贵实验。

持续优化以小批次进行：每轮优先解决一个已发现的误差或行为问题，保留对照，观察成熟后再决定下一轮。新增数据要证明可用性和增量，不因“有新闻”就让 LLM 直接接管策略。

18 运行质量与运维

记录采集时延、报价年龄、正式计划及时完成率、计划覆盖率、失败原因、模型运行时长、LLM 成本和账本未对账项。按市场显示分母，避免把港美股日历混为同一运行日。

初期 SLO 在本机基线测量后确定。建议目标是每个计划交易日都留下成功或失败回执、全部正式计划可追溯、冻结结果可复算；不得把尚未测量的页面速度或实时覆盖写成已达标。

SQLite 使用受控写者与一致性备份；长训练使用冻结快照，不持有生产写锁。日志不打印密钥和完整账户明细。备份、结果和原始证据有保留策略，删除前确认不破坏已发布评价的复现引用。

运行命令分别承担采集、对账、预测、计划、评价和发布，避免一个 all 命令在用户不知情时扩展为写私有账本加公网发布。现有命令的行为变化须写明并保持兼容或迁移提示。

18.1 资源与成本管理

首期优先使用现有 Mac、现有数据订阅和本地数据库，不把购买 GPU、付费消息队列或云数据库作为开工条件。M0 测量当前数据量、备份体积、训练时长与磁盘余量；据此确定任务窗口和保留期限，不能依据模型名字估计算力需求。

成本分别登记为开发投入、数据费用、LLM 调用、存储备份与维护时间。运行时大模型可配置每日调用数、token 与金额上限；达到上限时停止可选研究，不中断账本和基础预测。具体价格按实施时的真实服务核验，不在本书给出未经核实的套餐预算。

策略收益主表扣除交易费用；另设经济效果表扣除可归属的持续数据和运行费用，避免小幅交易收益增量被昂贵调用成本抵消。开发投入作为项目投入单列，不任意摊入某个短期回测窗口。

18.2 依赖与可复现性

仓库已有 Python 环境与部分固定依赖，正式实施应保存实际环境清单，并在隔离环境验证变更。生产所需依赖、可选实验后端与 LLM 接口分开；不能在网页启动时下载模型或安装库。

冻结实验同时记录代码 SHA、运行环境、实际后端、模型权重、数据版本、配置与 seed。外部服务输出缓存留档；模型或接口更新后作为新版本比较，不假设同名服务一定返回相同结果。
