## 3 切换日步骤（草案，逐步需授权）

> 每一步后做检查；任何一步失败 → 立即执行 §4 回滚。

1. **冻结窗口**：确认当日 V2 操作单已冻结/截止已过，没有进行中的 `coach run`/`intent`；记录 V2 `run_log` 最新 run_id。
2. 🔑 **备份**：V2 库做 SQLite 一致性备份（`sqlite3 data/mystock2.db ".backup 'backups/mystock2-pre-cutover.db'"`），确认可恢复；V1 库同样做一次备份（只读复制）。
3. 🔑 **改 V1 端口**：V1 私有 `config.yaml` 的 `web.port` 8888 → 8887；重启 V1 的 Web 服务。检查：`http://127.0.0.1:8887` 可打开、数据与切换前一致。
4. 🔑 **V2 切 8888**：V2 `config.yaml` 的 `web.port` 8889 → 8888；重启 V2 Web（`python -m mystock2 web`）。检查：`http://127.0.0.1:8888` 打开 V2；各视图新鲜度头部正常；未揭示的操作单仍显示「已密封」。
5. **并行对账**（过渡期）：每日对比 V1(8887) 与 V2(8888) 的持仓、成交、现金；V1 **不再运行采集**（共用富途账户额度）。
6. 过渡期满且无问题：🔑 **停用 V1**（负责人决定时点），V1 代码与数据只读归档，不删除。

## 4 回滚（数分钟）

1. 🔑 V2 `web.port` 改回 8889，重启 V2。
2. 🔑 V1 `web.port` 改回 8888，重启 V1。
3. 检查两边页面；V2 数据库与配置**不变**（前向记录不受影响）。
4. 记录回滚原因，登记 OPEN_ITEMS。

## 5 切换回执模板（COLLABORATION §5：逐条表态）

切换完成后写 `docs/records/cutover_claude_YYYYMMDD.md`：做了什么（按上面步骤）、**没做什么**（是否改过 V1 代码、是否碰过 V1 数据库、是否联网、是否发布、是否新增调度、是否有任何交易）、检查结果、备份路径（路径不入库）。
