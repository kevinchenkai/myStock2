# 协作约定（Codex × Claude × 评审模型）

> 生效：2026-10-05。借鉴 V1 `docs/COLLABORATION.md`，按 V2 精简。共用规则在 [AGENTS.md](../AGENTS.md)。

## 0. 唯一信道

**`docs/` + Git 是唯一协作信道。** 不读对方的会话、进程或工作树来推测进度。要知道对方干到哪 → 读 `git log` 与该轮文档；要交东西 → 提交进 Git；没写进文档的进度视为未确认。两方不同时改同一批文件。

## 1. 一轮协作的形状

```
用户提出目标 → [方案/工单] → [执行记录] → [独立审查] → [修复回执] → [交接] → 用户确认 → 合并
```

不必走满。小改动用提交说明即可；**只有跨会话、跨 agent、对方不读就接不上手的工作才立文档**。

## 2. 文档命名与位置

```text
docs/<prd|plans|records|research|guides|adr|protocols>/<topic>_<producer>_<YYYYMMDD>.md
```

| 目录 | 用途 |
| --- | --- |
| `prd/` | 产品需求与项目书（输入材料） |
| `plans/` | 现行实施方案与评审记录 |
| `adr/` | 架构决策记录（编号 `NNNN-标题.md`，不带作者日期，状态写在正文） |
| `protocols/` | 评价协议与冻结配置的说明（口径、参数、冻结日期） |
| `records/` | 工单、执行、审查、修复、部署、回执 |
| `research/` / `guides/` | 专题调研 / 使用与接手指南 |

- `producer` 是**原始执笔者**（`codex` / `claude` / `gpt` / `grok` / `cursor` / `human` / `unknown`），不是审查人或提交人；日期为文档身份日期（紧凑 `YYYYMMDD`），不随修订改名。
- 模型版本仅在有依据时写正文，不写进文件名。
- 例外：用户亲笔的原始材料（如 `docs/V2项目 idea.md`）保持原名。

## 3. 每份文档的头部

必须交代：**基线 SHA、分支／工作树、状态、边界（做了什么、明确没做什么）**。接手的人先看这里就能判断能不能信、能不能用。

## 4. 未尽事项与待决事项

跨轮次的待办**只登记在 [OPEN_ITEMS.md](OPEN_ITEMS.md)**，保留原始编号与出处；关闭时标记完成并写明由哪个提交／文档关闭，不删行。

## 5. 边界写「没做什么」

涉及真实账户与资金，每轮收尾要对下列事项**明确表态（只写核实过的）**：是否推送远端／合并 main；是否连接过真实券商接口或读取真实账户数据；是否读写过 V1 的运行库；是否向外部模型发送过内容（发了什么）；是否发布过公开内容；是否新增过调度；是否有任何真实下单。

## 6. 数据隔离

实验、迁移演练一律在隔离工作树＋数据副本里做；`data/`、`*.db*`、`config.yaml` 不进 Git；文档里不写真实持仓金额与账户明细，示例用合成值并标注。

## 7. 结论照实写

负结果照写，不调低门槛、不挑窗口；工程完成 ≠ 策略晋级；重建／回填 ≠ 前向；不确定就写不确定。对方写了不实结论，审查照实指出。

## 8. 多模型评审

方案与关键设计由多个模型独立评审（当前为 gpt-6.1 与 grok-4.7，执笔者 Claude）。规则：

1. 评审方**只出结论不改文件**；意见以 `must-fix / should-fix / nit` 分级，必须引用方案章节与理由。
2. 执笔方逐条给出处置（采纳／部分采纳／不采纳＋理由），写入 `docs/plans/` 下的评审记录，**不静默吞意见**。
3. 评审之间的分歧不由执笔方私下裁定：列出各方理由，交项目负责人决定。
4. 发往外部模型的材料只含已提交、已脱敏的文档，不含私有数据。

## 9. 提交信息

说清**为什么**；关联文档写路径、关联发现写编号；分批提交，别攒成巨型提交；协作产出带署名行（见 AGENTS.md / CLAUDE.md）。
