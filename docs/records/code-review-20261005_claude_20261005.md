## 1 总体判断

- 账本的核心不变量（只追加、Decimal、幂等、冲销链、开账边界）在 `ledger/projection.py` 这一套实现里成立，上一轮评审的修复都还在。主要风险出在**第二套实现**上：资产趋势的 `web/series.py` 和预测视图的密封判断，各自复刻了一遍规则，但只复刻了一部分。
- 4 条 P0 **当前都是潜伏的**：触发条件（开账更正、前向预测、比较批次、人工否决）在真实库里都还没发生过（没有比较批次，也没有前向预测）。但它们都在正式前向观察启动后的第一条路径上，必须在启动前修好。
- 采集层对富途返回的「非常规」行（卖空、被取消的成交、`'N/A'` 缺值、费用标题变化、映射改动后重放）处理偏乐观：有几处会**静默重复入账或静默丢行**，退出码仍为 0。
- 例行更新的「失败不中断」做得对，但有几条路径把「没做完」记成「成功」，导致后续时间点直接跳过（C-04、C-05）。
- 测试数量多，但有一批关键边界没有被锁定：7 个变异全部存活（第 6 节）。
