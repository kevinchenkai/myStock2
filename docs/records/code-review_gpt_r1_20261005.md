**1. 总体判断**

当前实现尚不足以支持可信的正式前向比较。只追加、Decimal、严格穿越和 `UNKNOWN→PAUSED` 的基本路径已实现，但开账更正、结算、协议冻结、时间证明和部分撮合路径仍有实质缺陷。以下问题能够改变现金、库存、执行资格或比较收益，现有测试不足以排除它们。本次为只读静态评审，未评审 `mystock2/web/`，未访问网络、修改文件或执行写库命令，也未运行测试及复现。下述数值均为合成复现值。

**3. 实现与方案／ADR 不一致之处**

- **§6、ADR 0001：** 开账冲销不守和式；开账包可以补写；FX 缺腿仍生效；股息支付未强制结清 G；结算计算不遵循更正后的有效事件；经济归属和更正请求内容未完整参与冲突判断。
- **§6A.1、WP4.2：** 冻结未证明状态归属、预测前向资格及完整时间链；状态重建使用最新数据，缺少输入截止和证据版本绑定。
- **§6A.2–3：** 真实记录时间可以回填；人类计划状态和有效期未执行；选择单元从币种袋级整组变成逐标的；部分作废条件仅存储、不执行。
- **§6A.4–5：** 初始状态缺应收应付、预留，成本和年龄被重置；E0 无法实现非零期初应收示例。
- **ADR 0002：** 最大现金费用预留不成立，买税漏扣；买入持有缺行情未传播 UNKNOWN；未知早期容量可能被后续成交掩盖；拆股日 coach 与执行状态不同。
- **§7、冻结与恢复契约：** 冻结登记未成为运行约束，pilot 资格未贯穿持久化；执行证据为空，旧 run 元数据可覆盖。

**4. 最值得补的 5 个测试**

1. **开账与更正的和式测试。** 开账现金／持仓更正、取消、同 t0 不同完整包，以及更正跨开账边界；断言精确余额，并验证错误请求完全回滚。
2. **协议与真实时间的端到端测试。** 冻结后修改费用／执行参数必须拒绝原批次；缺主假设或风险选择必须 pilot；任务跨截止、生产 `--now`、同秒微秒边界均不能取得正式资格。
3. **点时状态与拆股日完整流程。** 先冻结，再加入晚到修订；旧证据复算应一致，新证据恢复须显式关联。拆股日 coach、human_plan 与 engine 的开盘状态 hash 必须相同。
4. **费用与缺行情的执行矩阵。** 覆盖 BUY 税、fill 级 flat_fee、滑点预留、未知早期 volume、买入持有缺首 bar、规则未知；断言现金不越预算、费用与权益一致、未知状态正确暂停。现有 T-33 直接手填 E0=2,100，应补真正从初始状态计算 E0 的测试。
5. **veto 并发及故障注入测试。** 在基础单更新、状态改变、冻结提交后日志失败、两个响应并发时注入故障；断言只能有一次完整应用，不能出现“票已生效、成功回执缺失”，重试可恢复且不会重新绑定失效基础单。
