## 1 做了什么

复盘页点任意一行 → 弹窗最上面是「AI 评价 · 本机 Codex」，下面是原来的五栏复盘卡。
- 没有缓存：自动请求一次（弹窗里显示「Codex 正在评价这一笔（已 N 秒）」，每 3 秒轮询），完成后显示评价并写入数据库。
- 有缓存：直接显示，不调模型；底部「刷新评价」重新请求并**新增一行**（旧评价保留，页面取最新成功的一条）。
- 缓存过时提示：评价所用输入与现在不同（例如 +5/+20 日结果刚到期）时显示「输入已变化……可点刷新」，**不自动重发**。
- 失败：显示原因并保留上一次成功的评价；有「重试」。
- 命令行等价：`python -m mystock2 review deal --deal-id <id> [--refresh]`。

## 2 发给模型什么（脱敏摘要，白名单）

`replay/review_payload.py::build_payload`，顶层只有六块，对应测试 `test_payload_has_only_whitelisted_sections_and_no_identifiers`：

| 块 | 内容 | 时间口径 |
| --- | --- | --- |
| `instrument` | 代码、中文名、市场、币种 | — |
| `trade` | 日期、方向、数量、成交价、成交额、费用及费用占比、成交前/后股数、仓位变化（新建仓/清仓/±%）、卖出是否用到迁移而来、无成本记录的期初股份 | 事实 |
| `known_at_decision` | 用户事前意图（多数为「未记录」）、成交前已冻结 AI 单的**数量**（不含内容）、同一标的更早成交（最多 12 笔）、成交前行情背景：最近 20 个交易日 OHLC+量（未复权）、5/20/60 日收益（复权）、20 日波动率、250 日区间位置 | **成交前已知**（只含成交日之前） |
| `same_day` | 成交当日 OHLC+量、成交价在当日区间的位置 | 下单时**不可知**，只用于评价执行位置 |
| `hindsight` | +1/+5/+20 日涨跌（复权，未到期写「未到期」）、窗口内最大不利/有利变动、同一标的之后的成交（最多 5 笔） | **事后** |
| `gaps` | 数据缺口（如动机未记录） | — |

**不发**：账户号、成交号/订单号、现金与总权益、其他标的持仓、AI 操作单内容（只给「成交前已有 N 张已冻结单」）、任何密钥/路径。
数量、价格、费用是这笔成交本身的事实，必须发（否则无法评价），负责人已确认接受（调用的是本机 Codex 订阅，不经 API Key）。留痕的 `request_text` 就是实际发出的全文，可在库里审计「发出去了什么」。

## 3 架构与「Web 只读」的例外

- `review` 子包（`codex_runner`、`service`）：调 Codex、写缓存。只被 CLI `review deal` 使用；`web` **不得 import**（`tests/test_import_boundaries.py` 新增 `review` 声明）。
- 缓存表 `trade_review`（迁移 0013；写入者 `review`）：每次请求一行，`status` running→ok/error，**不可删除**（触发器）；存提示词全文、评价、模型/effort、提示词版本、输入哈希、耗时、错误。
- Web：新增隐藏视图 `trade_review`（GET，只读缓存＋判断是否过时）和**唯一的 POST** `/api/review/deal`。POST **不写库、不调模型**，只校验后以独立会话拉起 `mystock2 review deal`。防护：必须带自定义头 `X-MyStock2-Action`（浏览器跨站表单发不出）、`Origin`/`Sec-Fetch-Site` 同源、回环 Host、`deal_id` 白名单字符、成交必须存在、同一笔已有在跑的请求不重复拉起、已有缓存且非刷新不拉起。
- `AGENTS.md` 已写明这一例外；`tests/integration/test_web_readonly.py` 的「所有路由只读」检查改为只允许这一条 POST，并有测试证明 POST 处理期间 Web 进程不打开写连接。
- 为什么不让 Web 直接写：保持「Web 进程没有写权限」这条硬边界，评价缓存的写入走与账本同样的授权器路径。

## 4 提示词（`trade-review-v1`）

`review_payload.py::RULES`。要点（完整文本在代码里，改动须升 `PROMPT_VERSION`，旧缓存会被标为「输入已变化」）：
1. 只用「数据」里的信息，不编造新闻/财报/盘口/情绪，不联网；常识性背景须标「一般性背景」且不下具体结论。
2. **过程与结果分开评价**：过程只能依据 `known_at_decision`；`hindsight` 只评价结果，不得倒推「当时就该知道」；好结果≠好决策。
3. `same_day` 的高低收下单时不可知，只能评价执行位置。
4. 缺失数据直说「无法判断」；只有单笔样本，不推断整体水平。
5. 不预测、不给「现在该买/卖」；改进只写可检验的**流程规则**，≤3 条。
6. 迁移而来的无成本股份：不评价盈亏。
7. 评分口径：过程 1–5、结果 1–5（未到期写「未到期」）、置信度；固定的 Markdown 结构（结论／决策过程／执行／事后结果／做得好·可改进／数据缺口），≤600 字。

实测观察：评价能引用具体数值，并主动指出「动机未记录，无法检验是否按计划」；两次对同一笔评价都把 2000→1000 股的减仓与近期走弱放在一起讨论但没有下结论。

## 5 并发、中断与失败

- 同一笔同一时间只允许一个在跑：检查与插入在同一 `BEGIN IMMEDIATE` 事务里；POST 先查一次避免多余进程。
- `running` 行记录进程号：进程不在或超时（默认 900 s＋60 s 宽限）即视为中断，页面显示「上一次请求被中断」，不挡新请求。
- Codex 找不到/未登录/超时/空输出：落一行 `error`（含原因），不改旧的成功评价。
- Codex 调用：`codex exec --ephemeral --sandbox read-only`，空临时目录、关联网搜索、提示词走 stdin（参照 model-bridge 技能），模型/effort 来自 `config.yaml` 的 `review:`（默认 `gpt-6.1-sol` / `medium`）。

## 6 验证与已知问题

- 全量测试通过：新增 `tests/unit/test_trade_review.py`（输入脱敏与时间口径、缓存/刷新/失败/并发/中断、写权限、假 Codex 调用封装、视图状态、POST 防护）、前端 node 测试（无缓存自动请求→轮询→显示→刷新带 `refresh=true`）。
- 真实库：3 次真实调用；第 2 次打开同一笔 1.2 秒内显示缓存。
- **已发现并修复的缺陷**：首个版本的数字格式化把 `1000` 变成 `1`（`rstrip("0")` 误伤整数），导致第一条真实评价（review_id=1，HK.09926 2026-09-04 卖出）基于错误数量；已修并 `--refresh` 重评（review_id=2）。旧行因「只追加」仍留在表里，页面不会显示它（取最新成功）。
- 其他：弹窗里没有「上一笔/下一笔」；自动请求没有开关（点开一笔没缓存就会调一次 Codex，约 30 秒）；评价是否真有帮助要看后续使用，当前只是复盘参考。
- 顺带发现的既有不稳定：`tests/unit/test_web_stock.py::test_names_are_display_only_and_do_not_change_sealed_content` 曾在一次全量运行里失败、之后重复 4 次都通过（疑似泄漏值是短数字，偶尔与响应里的时间戳微秒位撞上）；未改，登记请 Opus 看。
