## 偏差与说明（如实）

1. **揭示是「格」级别的**：按要求以（批次、市场、目标日）是否存在揭示记录判断，**不核对揭示时的 `version_hashes` 是否覆盖了后来冻结的新版本**。即：揭示之后新冻结的盘前版本也会随该格显示。依据是首次揭示即锁定此前最后一个人类计划，此后的暴露不再影响 `human_plan`；若要更严格（只显示已被揭示过的版本），需改 `web/sealing.py`，请决定。
2. **揭示时间保守处理**：`revealed_at` 晚于当前时间（时钟偏差）视为未揭示。
3. **未揭示时的覆盖统计只给计数**：按「只返回已密封状态与计数」的字面要求，`missed_deadline/unavailable` 的行在密封期只计入计数，逐标的的行在揭示后才显示；因此密封期看不到「哪只标的缺单」。
4. **状态哈希校验的来源**：Web 无法重算线内状态，用「该批次最近一次 run 里该线目标日 `line_state.state_hash`」作为「当前状态」；没有 run 时标「生效（线内状态哈希未能校验）」，不是「已校验」。
5. **pilot 的判定**是视图自己的推断：执行协议版本（`exec-v1`）与教练协议版本（`protocol.yaml` 里的 `protocol_version`）是两套命名，库里没有二者的外键；视图用批次内操作单的 `protocol_version` 去匹配 `protocol_freeze`，并对「冻结时间晚于首张单」也判 pilot。批次内没有任何操作单（如只有 buyhold）时一律判 pilot（无法关联）。这是保守口径，判定规则应在协议登记里固定后再改。
6. **复盘「对照」栏**（AI 单与「不操作」反事实）仍未实现（M7 偏差 1）；页面明示。
7. **记分牌未做**：「下钻某日」、敏感性（费用×2、滑点、参与率）并列表、经济增量表（`run_cost`）；`ai_veto` 与 `ai` 的配对未做（只做了要求的两对）。块自助法的区间用 float 计算（统计量，不是金额），展示前转为 Decimal；样本 < 10 个配对日不给区间。
8. **数据状态**：行情「缺口」用日历判断，采集时钟是请求时刻（演示库时间停在 2026-03，用真实时钟打开时会显示大量「落后/缺口」，这是预期行为）；小时线归档检查只是 `hourly_archive_gaps` 的结构粗检；汇率不判缺口（无日历）。
9. **并行改动**：开发期间工作区里有他人同时修改 `core/timeutil.iso_utc`（固定微秒精度）、`coach/tickets.select_ticket`（整组原子选择、新增 `not_in_latest_group`/`expired` 原因）、迁移 `0007`、`cli/ops.py` 等；本批已据此调整（时间比较改用 `ensure_utc`，选择原因增加对应文案并对未知原因安全降级为「不采用（原因）」，补了整组原子选择的测试）。收尾时全量 422 项通过；其间 `test_daily_flow`、`test_ledger_fees_settlement_reconcile` 曾因他人改动一度失败，不属于本批，已在最后一次全量运行中恢复。
10. **测试辅助文件**按写入范围放在 `tests/unit/test_web_opsdata.py`（合成批次/操作单/暴露/run/回执，使用独特的哨兵值）。
11. 改了既有 M3 测试里的若干断言/列表：内置视图列表由 6 个变为 10 个、持仓「当前操作单」断言、`views.yaml` 顺序断言、空库用例。
