### 视图口径摘要

- **账户总览**：逐币种现金/持仓市值/应收/权益（原币种）＋券商快照现金；权益＝现金＋Σ数量×**未复权**收盘价＋应收；缺行情的标的使该币种市值与权益「不可用」（现金仍显示）。默认**不合计**；选基准币种后，每个币种都有可用汇率才给合计（路径可为直接/反向/经 USD 中转），并列出每段汇率的来源与日期；缺汇率→合计「不可用」并点名币种。对账状态来自 `ledger.reconcile` 与最近快照，未对账项逐条列出；无快照＝「未对账」。
- **持仓**：账本数量 vs 快照数量；券商成本（快照 `cost_basis` 原值，可空）、摊薄成本（快照无此字段→恒「不可用」）、本地移动平均成本三列并列；含开账快照成本标「估算」，含无成本证据股份标「部分」；角色来自标的名单（可选）；集中度＝占该币种持仓市值（币种之间不相加）；「当前操作单」列留空位「M6 提供」。
- **交易**：已入账成交（有效版本），每笔含币种、费用及按类型的归属明细、来源数、更正版本数、开账前标记；没有费用事件的成交显示费用「不可用」而不是 0；成交净现金流中性色、逐币种合计、注明「不是盈亏」。
- **盈亏**：已实现交易盈亏（费用后，不含股息/利息/汇兑），拆「精确」「估算」，无成本证据的卖出部分「不可用」（只给数量与净收入）；开账日（含）以前的成交单列、盈亏「不可用」（T-01）；「成交净现金流」独立命名。
- **资产趋势**：每个币种三条曲线分开命名——持仓市值、账户权益、剔除外部资金流的收益；缺行情的日子 `status=gap` 并列出缺哪些标的，前端断开折线、画灰带；外部资金流用三角标记，入金当天权益上升而收益不变（T-07）。
- **外汇**：USD/HKD/CNY 六个方向的换算路径（直接/反向/经 USD）、来源与日期，缺任一段「不可用」；单个币对的汇率历史与缺口（>4 天）；汇率不着色。

## 偏差与说明（如实）

1. **`snapshot_position.cost_basis` 的口径未知**：迁移与采集器均未规定每股还是总额。视图按**每股成本**展示，并用它作为开账持仓的成本估算（标「估算」）。M2a 采集器落地时必须确认；若是总额，持仓视图的券商成本列与盈亏的「估算」会错，需改 `ledgerdata.py`/`holdings`。
2. **未改 `pyproject.toml`**（不在可写范围）：`mystock2.web` 的 `static/*`、`views/*/{view.yaml,panel.js}` 目前只在可编辑安装（`pip install -e .`）下可用；若要做非编辑安装，需要在 `[tool.setuptools.package-data]` 里登记这些文件。**需要你决定/处理**。
3. **盈亏的三类股份按持股比例消耗**：移动平均成本下无成本证据／开账估算成本／精确成本的股份不可区分，卖出时按持股比例消耗；平均成本里只要还混有开账估算成本，整笔已知部分标「估算」，直到清仓。这是写死的口径（见 `ledger/pnl.py` 头注释），不是行业唯一做法。买入费用并入成本、卖出费用冲减收入；费用晚到会改变历史盈亏（因为是对当前账本重算）。
4. **新鲜度阈值**：每个视图 `view.yaml` 的 `stale_after_hours` 默认 72 小时（占位，未依据数据调参）；账本来源的采集时间取该账户最新 `received_at`，因此长期没有新事件也会显示「陈旧」（偏保守）。综合事件时间/采集时间取各来源中最旧者。
5. **行情**：估值只用 `quality='ok'` 的日线；`partial/stale` 不当收盘价，当前估值会回退到最近一个 ok 收盘并标「陈旧 日期」（不是不可用）；回溯 20 个自然日，更早视为缺行情。
6. **汇率**：换算接受比估值日早至多 `max_stale_days`（默认 4 天，覆盖周末/假日），并显示汇率日期与陈旧天数；超出即「不可用」。HKD↔CNY 无直接币对时经 USD 中转（web 内 `fxpath.py` 实现，`market.fx` 未改）。
7. **资产趋势**：日期轴＝本币市场交易日（USD→美股、HKD→港股，其他币种取并集）；基准日＝第一个可估值的日子；收益＝(权益变化)−(外部资金流)−(换汇划转)，换汇划转也被剔除是因为单币种曲线里它不是该币种的收益（换汇本身的盈亏未单独体现）；股息应收计入权益；非外部流的 `ADJUST` 计入权益变化并给出提示。未做按基准币种合并的趋势曲线。
8. **标的名单**：角色来自可选的 `universe.path`（配置里的额外键，未改 `core.config`），缺省为 `config/local/universe.yaml`（存在才用）；无名单显示「未配置」。
9. **视图静态检查**：除只读连接外，注册时对 `query.py` 做 AST 检查，禁止导入联网/采集/训练/子进程模块、禁止出现写连接与迁移名字、禁止直接调用 `utc_now()`（须经 `common.now_of(params)`）；扩展视图不过检查则被拒并在 `/api/views` 的 `problems` 里可见，其余视图不受影响。这是「视图模块受代码审查」的机械部分，不能替代人工审查。
10. **测试辅助文件**：按写入范围约束，共用的合成数据与应用工厂放在 `tests/unit/test_web_fixtures.py`（它本身也含一个冒烟测试），其余 `test_web_*.py` 从那里导入。
11. 开发中遇到一次**他人并行改动造成的瞬时失败**：另一路在 `core/db.py` 登记新写入者期间，`tests/unit/test_db.py::test_unregistered_owner_and_migrator_owner_rejected` 短暂失败（`replay` 已被登记，测试以它作「未登记写入者」）；本批收尾时全量已通过，**该测试的假设值得由其负责人复核**（不属于 M3 范围，未改）。
