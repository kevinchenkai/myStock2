### 密封（与「最新预测」的一处取舍，需要负责人知情）

实施方案 §6A.2 规定：**目标日的预测区间、由冻结参数推出的限价**与 AI 单等价，在人类计划锁定前，Web 与 API 默认不得显示（M3b 已按此做了「操作单」密封，并有全路由泄露测试）。而 `prediction_version` 里「最新 as_of 的预测」其目标日往往尚未结束，正是被密封的对象。因此本视图对最新预测表采用：

- **目标日已有终值日线（目标日已结束），或该市场该目标日已有揭示记录（`intent_exposure`，`revealed_at` ≤ 当前时间）→ 显示低/高价位、相对基准收盘价的位置和实际值**；
- **否则显示「已密封」，响应里不含任何价位/区间字段**（有测试：哨兵值不出现在任何参数组合的响应里；别的市场、别的目标日、晚于当前时间的揭示都不能解封）；
- 密封行下面另列一行「最近已结算」（该标的最近一次目标日已结束的预测），让页面仍有可看的内容。
- 统计与图表只用目标日已结束的样本，不受影响。

在真实库上的实际效果：港股标的的最新预测（目标日已有行情）显示价位；美股标的的最新预测目标日尚无行情，显示「已密封」，其下为最近已结算一行。若负责人认为 rebuilt 预测不应受密封约束，需改 `query.py` 的 `_latest_row` 并同步更新 §6A.2 的说明——这是**策略层决定，我没有擅自放开**。

### 浏览器检查

开发服务用 8889（读真实库 `data/mystock2.db`，Web 只读连接）。桌面（内置窗格 1024 CSS 像素宽，深色）逐段看了头部/来源、对比表、预测带图（窗口 60 与 250、不同标的）、最新预测表；`source=forward`（无前向样本）的空态；375px（浅色与深色）下表格折成卡片、图表缩放到容器宽度，`scrollWidth == innerWidth == 375`，面板内没有任何元素右边界超出视口；控制台无错误。截图在内置浏览器会话里，不在仓库。检查中发现并修复：①「预测落后于行情」最初按全局比较，会把「目标日行情比 as_of 新」这种正常情形误报，改为逐标的比较（as_of < 该标的最新行情日）；②最新预测表原 12 列在 1024px 下需要横向滚动，改为「低 – 高」合并列＋相对位置副行；③对比表表头缩短、名义目标移到表上方。检查完已停止服务并确认 8889 无监听；未测 1100px 以上。

## 偏差与说明（如实）

1. **密封取舍**见上；这使得「每个标的最新 as_of 的价位」对目标日未结束的预测显示为「已密封」，与任务字面要求（直接显示）不同，原因是 §6A.2 的既有硬规则。
2. **只比共同样本**：两个模型的预测起点不同（LGBM 需要更长训练窗口，起点更晚）。对比表只在「两个模型都有预测、且目标日已有终值日线」的样本上算，页面有提示；各模型自己的预测条数/已有实际值数在来源卡片里单列。
3. **版本选择**：每个模型家族（`naive*`→基线，`lgbm*`→LGBM）只取「最近生成」的 `model_version`，其余版本与不识别的模型只在警告里列出，不混算。名称按家族前缀匹配（`naive-vol-v1`、`lgbm-cqr-v1`；兼容下划线写法）。
4. **汇总行**：覆盖率、宽度、pinball 按样本合并，**改善**取各标的改善的等权平均（门槛口径），两者口径不同，页面已注明；样本 < 30 的标的不入汇总与门槛（列在「未纳入判定的标的」），不是按 0 算。
5. **新鲜度头部对 rebuilt 的含义**：rebuilt 预测的 `generated_at` 是重建时刻，头部「新鲜」只表示重建刚发生，**不表示预测在当时可得**；头部备注与来源卡片都写明了这一点，并给出 as_of 与行情日的对照。陈旧阈值 `stale_after_hours` 取 96（与记分牌一致，占位）。
6. **图表价位口径**：竖条是原始（未复权）价，预测带用 `low_price/high_price`（原始价口径，以 T 日原始收盘价换算）；突破点按复权比例判定（与表格一致）。遇到拆股/大额除权日，带与竖条在该日附近的视觉位置会与突破判定不一致（判定是对的，图是近似），页面脚注已说明价位口径；未做复权价曲线。
7. **价位展示 2 位小数**（库内 4 位，`v` 保留原精度）；覆盖率 1 位小数、宽度 2 位、pinball 以「占收盘价百分比」4 位。
8. **图表 `symbol` 选择器**：改了 `app.js` 的参数栏，使 `symbol` 参数用视图返回的 `codes` 渲染下拉（与已有的 `account` 处理同一模式）。若以后别的视图也要动态下拉，可沿用该约定。
9. **集成只读遍历**（`tests/integration/test_web_readonly.py`）自动覆盖 `forecast` 路由（库字节/mtime 不变、无写 SQL、无网络、全新解释器里 `forecast/collectors/assistant` 未被加载）；**没有**把 `forecast` 加进该测试里的「密封态泄露哨兵」检查名单——那份夹具故意在已结算的目标日也放了带哨兵价位的预测，而本视图对已结算目标日显示价位是设计行为；密封行为由 `test_web_forecast.py` 自己的夹具覆盖。
10. **真实库在检查期间有他人写入**：`ps` 看到一个 `collect futu … --what cashflow` 进程（8:16 启动，非本批启动）在写 `data/mystock2.db`（`-wal` 有更新）；本视图只经 `mode=ro` 连接读取，不是写入者。
11. 临时创建的 `.claude/launch.json`（供内置浏览器启动 8889 服务）已删除，未留在仓库。
12. 视图不区分「AI 线是否使用了这些预测」：预测效果是预测层指标，**不回答「更赚钱吗」**，策略收益仍只看记分牌。
